# 相关-参数速查-TUNING.md —— 控制台「高级设置」里 25 个滑条 + 12 个勾选分别管什么

> 【相关】调参 / 看不懂控制台滑条时读。**每项只讲「调会发生什么」**，设计原因见
> `01-规范/必读-防回退清单-DO_NOT_REVERT.md`；地址与常量见 `02-内存布局/相关-游戏内存映射-MEMMAP.md`。
> 滑条都在控制台的「高级设置」窗口里；下表「默认」= 出厂默认（= 用户实机固化并替代的那一组）。

## 一句话职责

控制台滑条的速查表：哪个参数管哪件事、调大调小各有什么后果、改完跑哪条命令验。

## 什么时候需要读取

- 想改走位但不知道动哪个滑条；
- 改完发现更糟，怀疑动错了参数。

## 核心构成：四层结构

```
第 1 层  安全判定    → 哪条路会死？（先筛出候选方向）
   ───── 安全分数线 comfort：宽裕档 / 紧张档的分界 ─────
第 2 层  走位偏好    → 安全的路里选哪条？
            宽裕档（有方向间隙 ≥ comfort）：软项全权重参与
            紧张档（都没有）：只在与最优相差 ≤ risk、且间隙 ≥ 0 的方向之间参与
第 3 层  保命兜底    → 真的躲不过 / 已经被打中 → 放技能（灵击）
第 4 层  关卡与会话  → 打完这一关接不接下一关？你自己上手时它停不停手？
```

`px` 是**游戏逻辑坐标**（场地 384×448），不是屏幕像素：48px ≈ 场地高的 11%。

## 第 1 层：安全判定

| 参数 | 默认 | 管什么 | 调大的后果 |
|---|---|---|---|
| 弹道外推帧数（horizon） | 10 | 子弹弹道外推几帧（30 帧 ≈ 0.5 秒） | 躲得更早更保守；对慢速弹过度反应 |
| 自机速度（px/帧） | 4.39 | 推演时假设自机每帧走多远 | **已实测标定，别乱改；填错全盘失真** |
| 额外安全裕度（px） | 0 | 判定半径外再留多少余量 | 把「擦弹」也算危险，更怕死 |
| 安全分数线（px） | 1.0 | 间隙达到它才算「这条路安全」 | 软项更难参与，走位更死板 |
| 弹幕预警窗口（帧） | 10.0 | 敌人还有这么多帧发弹时，提前放大它的危险半径 | 更早躲开发射点，更保守 |
| 预警危险半径（px） | 10.0 | 发弹瞬间要躲开多远 | 离即将发弹的敌人更远，也更难贴上去输出 |

> 预警**改的是安全分本身**（不是走位偏好）：它把「马上要喷弹的敌人」暂时当成更大的威胁。
> `预警窗口 = 0` 即完全关闭。它只预测**下一波什么时候来**，不预测弹幕形状。
>
> **空旷区吸引**问的是「这一带弹多不多」，与安全分（「最近那颗会不会撞上」）分工不同：
> 逐帧挑「当前间隙最大」只是局部最优，密集弹幕里那常常只是弹与弹之间的一条缝，
> 钻进去越走越窄。它用**自己的前瞻**（`CLEAR_STEP`，12 帧 ≈ 53px）——
> 4 帧的落点彼此太近、没有区分度（实测同帧极差 0.20、决策差异率仅 1.2%）。
> 详见 `01-规范/必读-防回退清单-DO_NOT_REVERT.md` 的「例外」段。

## 第 2 层：走位偏好

| 参数 | 默认 | 管什么 | 调大的后果 |
|---|---|---|---|
| 贴边惩罚权重 | 24.0 | 离边界 60px 内扣分，防贴边丢机动空间 | 更主动回场地中部 |
| 进攻吸引权重（0 为不追） | 30.0 | 朝目标（上方敌人，BOSS 优先）靠拢的力度 | 更主动贴向敌人输出，也更危险 |
| 输出保持距离（px） | 99.0 | 输出带**下沿**：停在目标下方 99~179px | 站得更远更安全 |
| 道具吸引权重（0 为不捡） | 50.0 | 去捡掉落道具（P 点 / 蓝点 / Bomb / 1UP）的力度 | 更主动去捡，也更常离开输出位 |
| 道具等待窗口（帧） | 60.0 | 愿意为一块道具等的帧数：道具还要更久才落到自机高度就不追 | 更早动身、更常提前占位；**0 = 只在道具已到自机高度时才动** |
| 道具线触发价值 | 0.0 | 满火力时场上普通掉落总价值 ≥ 它就冲上收集线（y<128）全屏吸一次 | 更挑剔，攒更多才冲；**0 = 满火力且有普通掉落就冲** |
| 同等安全容差（px） | 1.0 | 紧张档里允许参与排序的安全差（与最优方向的间隙差） | 更主动贴向输出位，也更常选到间隙略小的方向；**0 = 退回纯躲** |
| 同向惯性奖励 | 0.7 | 与上一帧同向时加分，抑制抖键 | 更黏在旧方向上 |
| 安全余量权重 | 8.0 | 都安全时，间隙大的方向优先 | 更远离敌人，减少「刚够安全就贴」 |
| 空旷区吸引权重 | 25.0 | 同等安全时优先往「这一带弹少」的方向退（治逐帧钻缝） | 更主动往大空档转移；过大就不再优先输出，**且会明显更爱退到边角**（影子推演：关 8% → 25 时 31% → 60 时 42% 的帧终点落在角落）—— 边角天然弹少是本项的固有倾向，只能靠权重收着 |
| 空旷度评价半径（px） | 110.0 | 以落点为圆心、这么大范围里的弹密度 | 看更远的全局形势、更早转移；**但别超 ~150** —— 半径覆盖全场时九向弹密度同时饱和到 1.0，本项恒为常数、完全失效（999px 实测差异率 0.0%），200px 起还会为正空旷让出安全分（实测 10.49→7.70）。要更强的空旷吸引请加**权重**，不是加半径 |
| 自动回中权重 | 15.0 | 离场地中心超出自由半径就往回拉（治在角落与顶部恋战） | 更常待在场地中部；**过大就与进攻吸引对抗** |
| 回中自由半径（px） | 110.0 | 离中心这么近完全不干预，软项自由发挥 | 更宽松、只在很偏时才拉；调小 = 更常待在中心附近 |
| 方向切换门槛 | 0.4 | 新方向优势不够就维持原方向 | **超过 0.5 就开始粘住该动的** |
| 安全时反应延迟（帧） | 7.0 | 局面宽裕就慢半拍再动（像人，不是每帧即时响应） | 更从容、切换更少；**再往上会增抖**（延迟与迟滞叠加会过冲回摆） |
| 低速模式（勾选） | 开 | 只需微调时按住 Shift 走**半速**（走位更细、射击形态收束） | 关掉 = 全程高速（旧行为） |
| 低速门槛余量（px） | 12.0 | **原地不动**的间隙 ≥ 安全分数线 + 它，才敢切低速 | 更少进低速、更常保持机动；**0 = 原地不比分数线差就用低速** |

> 反应延迟是**唯一只在安全侧生效**的参数：危险时它自动归零，立即执行（高手也是危险时反应最快）。
> 它的安全底线是 `max(安全分数线, 6px)` —— **把分数线调低不会连带放松延迟闸门**（两者职责不同：
> 分数线管软项能否参与，底线管能不能慢半拍）。
> **实测拐点是 4 帧**（≈67ms）—— 4 帧把密集弹幕的方向切换降了三分之二而不损安全，
> 8 帧反而更抖也更危险；**当前默认 7 帧是用户实机沿用的值**（偏「像人」，已超出拐点）。
> 完整实证数字 → `00-入口/必读-项目现状-CONTEXT.md` §3.13；
> 自己复现 → `py tools\humanize_sweep.py`。

> 进攻与捡道具是**同层竞争**：两者都在拉自机的位置，权重决定谁赢。火力未满时 Power 类
> 道具自动 ×1.8，所以默认值下补火力的优先级高于贴敌人输出。
>
> **捡道具带时间模型**：自机只在道具快落到自己高度时做水平对齐 —— 还在高处的不追（不干等）、
> 来不及的不追（不白跑）、在自机上方的只水平对齐（不上追）。有可打目标时还要求**顺路**
> （离目标对齐线太远的道具价值被压低）—— 打得到 → 敌人才会死 → 才继续掉道具。
>
> **捡道具带集群加成**：挤在同一落点附近（水平 56px 内、到达时间差 60 帧内）的一片道具
> 互相抬价 —— 方向选择比的是「一趟能捡最多」，不是「单块最值钱/最近」。散射中的道具
> 按终点近似 + 延迟计入；追踪中的（已朝自机飞）不参与吸引。
>
> **智能道具线**（勾选开关，默认开）：满火力（128）且普通掉落总价值 ≥ `道具线触发价值` 时，
> 冲上收集线一次全屏吸 —— 收集线只在满火力时存在，火力不满冲了也白冲。
> 冲线吸引**替代**进攻/道具吸引（不是叠加），安全分永远压过它：被弹幕堵住冲不上去，
> 5 秒冲不过就放弃并冷却 4 秒，绝不硬闯。
>
> **紧张档**是 boss 战能不能输出的关键：弹幕密时几乎没有方向达到安全分数线，旧逻辑此时
> 完全不追目标。现在允许「与最优方向相差 ≤ `同等安全容差`、且间隙 ≥ 0」的方向用软项决胜负。

> **「安全分数线」是整套参数唯一的闸门**：它调到 1px 等于让软项在几乎任何方向都能参与排序。
> 判定半径只有 `PLAYER_R + BULLET_R = 4.25px`，间隙 1px 意味着弹心距自机约 5px ——
> 而 `horizon` 越大，外推的累积误差越大。别把安全和偏好一起放松。

## 第 3 层：灵击（保命兜底）

| 参数 | 默认 | 管什么 | 调大的后果 |
|---|---|---|---|
| 自动灵击（勾选） | 开 | 被打中时自动按 X 放技能保命 | 关掉 = 不救，掉命就掉命（对照用） |
| 必死预判提前（帧） | 1.0 | 九向外推这么多帧全重叠就提前炸；**0 = 只做死亡炸弹抢救** | 判据变宽、更早炸，更不容易被碰到，但可能白扔炸弹 |

> 两条触发路径（`tools/dodge.py` 的 `BombGuard`，依据 → `02-内存布局/相关-游戏内存映射-MEMMAP.md` §11）：
>
> ① **死亡炸弹**：被击中的那一刻起有 **8 帧窗口**（`respawnTimer` 逐帧递减，**到 0 才结算掉命**）。
> 窗口内按 X 会执行角色 bomb 的 calc，把 `playerState` 改成 INVULNERABLE —— **死亡被取消**，
> 只消耗一颗炸弹。这条**始终生效**，与滑条无关（真高手最标志性的操作）。
> ② **必死预判**：九向外推全部与威胁重叠 = 不炸必死，所以这一炸不会浪费；
> 它抢在碰撞判定之前生效，比死亡炸弹更稳（不依赖那 8 帧窗口）。
>
> 三道「不浪费」的闸：没炸弹不炸、灵击已在生效中不炸、无敌 / 复活中不做预判（本来就死不了）。
> 窗口只有 133ms，所以发键按住 3 帧再松开 —— bomb 认**按下沿**，同帧 down+up 会被游戏轮询漏掉。
>
> 实机验证 → `py tools\verify_bomb.py`（切前台、自机挨打，三条判据同时成立才算救回）。

## 第 4 层：关卡推进与接管

| 参数 | 默认 | 管什么 | 关掉 / 调大的后果 |
|---|---|---|---|
| 自动进下一关（勾选） | 开 | 关卡过渡不退出；开场对话在无威胁源时轻点 Z 推进 | 关掉 = 打完一关就停（旧行为） |
| 玩家操作时让位（勾选） | 开 | 检测到真人按键就停手（松键、一个键都不发） | 关掉 = 全程不让位，想自己上手得先按「停止」 |
| 掉命后继续（勾选） | 开 | 掉一条命后不退出、接着打（含掉到残机 0 那次） | 关掉 = 一掉命就松键退出，也就等于不接最后一条命 |
| 让位静默时长（秒） | 2.0 | 人最后一次按键后再静默多久才接管回来 | 调大 = 人放手后有更长的调整时间 |

> **死亡黑匣子（勾选，默认关）**：**诊断项，不影响避弹决策**。
> 掉命时把前 4 秒完整现场（自机 / 全弹含运动参数 / 全激光 / 全敌人 / 输入位图）
> 落盘到 `_tmp\death_*.npz`，事后 `py tools\death_report.py _tmp\death_*.npz` 解剖真凶。
> 它复用主循环**已经读到**的世界，只多 3 个小读（focus / 输入位图 / 火力），
> 另起进程录会多抢一份 2MB/帧 带宽、把脚本挤到掉帧 —— 所以要用就勾这个。
> 与「掉命后继续」同开可在一局里连存多例（上限 8）。详见 `00-入口/必读-项目现状-CONTEXT.md` §3.27。
>
> **它怎么知道是「人」在按**：低级键盘钩子只认**非注入**事件
> （`LLKHF_INJECTED` 位 + 自定义 `dwExtraInfo` 标记）—— 脚本自己发的键不会被算进来，
> 否则一开枪就会「让位」给自己。**玩家一直按着键时不接管**：判据是「最近 N 秒有按键
> **或** 此刻仍按着键」；只看时间窗的话，人按住方向键时窗口一过就会被抢走手柄。
> 玩家按着的键也不会被脚本硬抬（抬键会改系统键状态表，把人家顶掉）。
> 单独验钩子 → `py tools\human_watch.py --seconds 8`。
>
> **自动进下一关为什么不用按键**：关卡结束 → 下一关是**游戏自己**载入的（中间的
> `curState=3` 过渡态，`GameManager::AddedCallback` 里 `currentStage++`）。
> 真正需要按的是**关卡开场的对话** —— 对话只认按下沿，而自动射击是按住 Z，按住永远推不动它。
> 所以只有「场上没有弹幕 / 敌人 / 激光」时才轻点（0.6s 一次）：战斗中绝不轻点，
> 不会打断连射。关卡过渡等超 120 秒判定卡死并退出；主菜单内部分屏仍不盲按（判据未定位）。
>
> **残机 0 不是退出条件**：残机是备用命，最后一条命照常避弹（`tools/screen.py` 的 `NO_LIVES`）。
> 停手只在两处：死亡结算完（`respawn <= 0`，赶在 Continue 出现之前松键）与 Continue 画面本身。
> 护栏 `py tools\check_autofire.py` 的残机 0 用例。

## 必须遵守的规则

1. **安全永远压过偏好**：只有存在间隙 ≥ `安全分数线` 的方向时，第 2 层参数才全权重参与排序；
   紧张档时也只在**间隙 ≥ 0 且与最优相差 ≤ `同等安全容差`** 的方向之间参与。
   任何时候它们都不会把自机送进必死方向。
2. **`自机速度` 是唯一必须先实测的参数**：其余参数只在它正确的前提下才有意义。
   已标定 `4.39`，唯一真源是 `tools/offsets.py` 的 `PLAYER_SPEED` —— 别在各文件里另写一份。
3. **`方向切换门槛` 不超过 0.5**：超过会让「贴边该脱出」「半路该继续对齐」都被粘住。
4. **反应延迟只在安全侧生效，危险时自动归零**：判据与理由 → `01-规范/必读-防回退清单-DO_NOT_REVERT.md`。
   **别把它改成无条件延迟** —— 那就是拿命换像人。

## 数据流 / 怎么调

| 想要的 | 调这个 |
|---|---|
| 别老往敌人身上凑 | 进攻权重 ↓ 或 攻击保持距离 ↑ |
| 更怕死、留更多余量 | 安全裕度 ↑ 或 安全分数线 ↑ |
| 少些来回微动 | 安全余量权重 ↑（**别加大方向切换门槛**） |
| 越躲空间越窄、被「磨死」（逐帧钻缝） | 空旷区吸引权重 ↑（默认 25，上限 60）；**半径保持 110 别加** |
| 老爱往角落 / 顶边跑（本项的副作用） | 空旷区吸引权重 **↓** —— 它本来就是「往弹少处退」，边角天然弹少；回中权重 ↑ 也有帮助；**贴边权重加大没用**（只在落点离边界 60px 内生效） |
| 想让它更早往大空档整体转移 | 只微调空旷区吸引权重；**别加评价半径**（覆盖全场即饱和失效，见上表） |
| 觉得它老想往中间跑、不肯贴着边躲 | 自动回中权重 ↓（**0 = 关闭**）、回中自由半径 ↑ |
| 只躲不打 | 进攻权重 = 0 |
| 多捡点掉落物 | 捡道具权重 ↑；**0 = 完全不捡** |
| 被道具牵着走、想专心输出 | 捡道具权重 ↓（或 `--no-item`）；道具等待窗口 ↓ |
| 道具还在高处就跑去下面干等 | 道具等待窗口 ↓（0 = 只在道具已到自机高度时才动） |
| 满屏掉落想一次全收 | 勾「智能道具线」（默认已开）；触发价值默认已是 **0 = 有掉落就冲** |
| 冲线太频繁、想攒多再冲 | 道具线触发价值 ↑（4.0 ≈ 4 小P / 3 蓝点） |
| 不想让它冲线 | 勾掉「智能道具线」或 `py tools\dodge.py --no-poc` |
| boss 战只会躲、不贴近输出 | 同等安全容差 ↑（默认 1；**0 = 退回纯躲**） |
| 躲得更早 | 弹道外推帧数（horizon）↑ |
| 动作别那么机械、少点每帧改主意 | 安全时反应延迟 ↑（当前 7；仿真拐点 4，**再往上会增抖**） |
| 想让它贴弹幕时走得更细 | 低速门槛余量 ↓（默认 12；**0 = 原地不比分数线差就用低速**） |
| 觉得低速拖慢了转移、躲不掉了 | 低速门槛余量 ↑，或勾掉「低速模式」 |
| 它常年半速、想让它只在微调时慢 | 低速门槛余量 ↑（判据是「原地不动的间隙」，调大即收紧） |
| 动作太迟钝、道具/对齐跟不上 | 安全时反应延迟 ↓，0 = 完全关闭 |
| 老是被打死、想让它自己放技能 | 勾选「自动灵击」（默认已开） |
| 炸弹用得太快、想省着点 | 必死预判提前 ↓（**0 = 只在被击中后抢救，最省**） |
| 想看它救了几次 | 日志的「死亡炸弹」「必死预判」行；控制台状态栏有「炸弹 N（已放 M）」 |
| 对照：不放技能会怎样 | 勾掉「自动灵击」或 `py tools\dodge.py --no-bomb` |
| 关卡打完就停、不想自动接下一关 | 勾掉「自动进下一关」或 `py tools\dodge.py --no-advance` |
| 想自己上手打一段 | 直接按键盘就行（默认会让位）；不想让它让位 → 勾掉「玩家操作时让位」或 `--no-yield` |
| 松手后它接管太快 / 太慢 | 「让位静默时长」↓ / ↑（默认 2 秒） |

绝大多数情况**只动上表前四个就够**。滑条都在控制台的「高级设置」窗口里，运行中改动即时生效；
但改了 `tools/` 下的代码要重启控制台（Python 不重载已导入模块 → `01-规范/必读-动手前的坑-PITFALLS.md`）。

## 存成默认值

**出厂默认就是用户实机固化的这一组** —— 数值写在 `tools/dodge.py` 的 `default_params()`
与文件顶部常量区（唯一真源）。原先存这组值的项目根 `dodge_params.json` 已注销
（备份在 `_tmp/dodge_params.bak.json`）：出厂即等同于它，留着就是第二处真源。
控制台里再点「保存为默认值」会重新写一份 —— 那是「你后来改过的覆盖值」，出厂默认不依赖它。

调出新的一组后，点「高级设置」窗口底部的 **「保存为默认值」** —— 写回项目根 `dodge_params.json`，
下次打开控制台自动载入（日志会提示「已载入保存的默认值 N 项」）。底部标签随时显示
当前用的是**出厂**还是**已保存**。点 **「恢复出厂默认」** 撤销，界面同时拨回出厂值。

| 事项 | 说明 |
|---|---|
| 存了什么 | 界面上的全部参数：所有数值滑条 + 9 个勾选项（自动射击 / 自动灵击 / 纳入敌人本体 / 纳入激光 / 开场按 Z 解除暂停 / 掉命后继续 / 失败菜单按 Z 继续 / 低速模式 / 智能道具线 / 自动进下一关 / 玩家操作时让位 / 死亡黑匣子）|
| 没存什么 | `dry`、帧数上限、循环周期这类运行状态 —— 固化它们会让下次启动带病开门 |
| 出厂默认在哪 | `tools/dodge.py` 的 `default_params()`（唯一真源；数值常量在同文件顶部）|
| 命令行受影响吗 | **不受保存文件影响**。`py tools\dodge.py` 的 argparse 默认同样取自 `default_params()` —— 两边同源，不会分叉 |
| 文件坏了怎么办 | 忽略并退回出厂默认，日志报错，**不覆盖原文件**（可自己修或删）|
| 手改文件有用吗 | 有用，但只认已知键与类型；未知键、类型错位的项会被静默忽略 |

## 实现细节

- 每个参数的滑条悬停 0.4 秒出悬浮说明，文案在 `tools/dodge_gui.py` 的 `PARAM_HELP`；
  滑条与勾选都在「高级设置」Toplevel 里（`dodge_gui._build_advanced()`），日志在另一窗口（`_build_log()`）。
- 常量与默认值的唯一真源是 `tools/dodge.py` 顶部常量区；**出厂默认的键集合**是
  `tools/dodge.py` 的 `default_params()`（存取函数 `load_saved` / `save_saved` / `clear_saved` 同处）。
- 滑条上下限必须容纳实际会用的值（`item` 上限曾是 40，装不下 50；`human_idle` 下限曾是 0.5，
  装不下 0.2）—— 装不下时箭头一点值就跳变。
- 反应延迟是 `plan()` 与按键之间的独立一层（`tools/dodge.py` 的 `ReactionGate`），
  不改任何安全分；护栏 `py tools\check_plan.py` 用例 19–24。
- 灵击同样不改评分（`tools/dodge.py` 的 `BombGuard`）：它只在「被打中」或「九向必死」时
  往按键集合里多塞一个 `X`，与方向键同走 `apply_keys`；护栏 `py tools\check_autofire.py` 的灵击用例。
- 激光余量（`LASER_MARGIN`，`tools/dodge.py` 顶部常量，默认 **16px**）**是进安全分的**：
  躲避要把激光线多让开一个身位（激光不动、一道挂几十帧，贴着它输出时惯性一推就滑进去）；
  必死预判不受它影响，仍按真实几何。护栏 `py tools\check_plan.py` 用例 36。
- 关卡推进与让位也在评分之外：`StageFlow`（`tools/dodge.py`）只管「退出还是等」与
  「要不要轻点一次 Z」；让位（`tools/human_watch.py`）期间方向强制 `none`、Z 与 X 一概不发。
  护栏 `py tools\check_autofire.py` 的进关 / 对话 / 让位用例。
- 低速模式**不是**一个开关就完事：判据是「**原地不动就够安全**」（`scores['none']` ≥
  分数线 + `focus_slack`）—— 站着不动都不险 = 这一步只是微调。每帧对快 / 慢两个速度
  **各跑一次 `plan()`**，慢的那次够不到门槛就保持高速（`tools/dodge.py` 主循环，`FOCUS_*` 常量）。
  必须重规划而不能复用高速结果 —— 间隙是按 speed 外推的轨迹算的，拿高速轨迹走低速
  等于「以为走得到、实际少走一半」。**必死预判也跟着当前速度走**（低速下能走的路只有一半）。
  冲线期强制高速；已在低速时门槛打折（`FOCUS_EXIT`），否则会在门槛上下逐帧横跳。
  护栏 `py tools\check_autofire.py` 的低速用例。

## 常见问题

- **改了没反应**：看日志首行的画面判据；非「关卡进行中」时脚本不发方向键。
- **改了代码没反应**：控制台仍在跑启动那刻的模块，关掉重开（桌面快捷方式）。
- **想验证改动的效果**：`py tools\sweep_params.py`（软项参数，三判据同时看）；
  改反应延迟用 `py tools\humanize_sweep.py`（同样三判据：安全 / 切换次数 / 对齐与拾取）；
  改捡道具用 `py tools\item_sweep.py`（收集率 vs 对准 boss 的帧数，多种子平均）。
- **想知道某一帧为什么选这个方向**：`py tools\explain_plan.py`（只读，附影子轨迹与道具项分解）。
  影子轨迹是「世界冻结」的推演，能直观看到自机会不会走到掉落物上。
- **想确认灵击真的救得回来**：`py tools\verify_bomb.py` —— 切前台、自机不动等挨打，
  进死亡窗口就按 X；**会挨打，救不回来就掉一条命**（这正是真实验证）。
- **想确认 Shift 真的被游戏收到**：`py tools\verify_focus.py` —— 只按 Shift、不按方向键
  （自机不动），读输入位图 bit2；附近有子弹就拒绝执行。
  想量低速的实际速度：`py tools\calib_speed.py --focus`（预期 = 高速的精确一半）。
- **运行中自己按方向键、自机却还在自己动**：看日志有没有「检测到玩家操作」。
  没有 → 「玩家操作时让位」被勾掉了，或键盘钩子没装上（日志「键盘钩子未能安装」）。
  单独验钩子：`py tools\human_watch.py --seconds 8`（按几个键，看有没有计数）。
