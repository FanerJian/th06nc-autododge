# 必读-文档编辑纪律-DOC_GUIDELINES.md —— 自更新 / 编辑 / 新建

> 【必读·P0】本库文档的维护规则。改任何文档前先读。
> 通用方法论不在本文件维护。

## 1. 核心原则

- 只反映**当前真相**，不是历史。
- 信息**只留一份**：一处详述，另处指路。
- 改完应**变短或持平**。
- 删而不藏：过时内容直接删，不写"（旧版已废弃）"这类墓志铭。

## 2. 文风：极简叙事（强制）

结论前置；一句一事；能列表不写段落；单句 ≤ 40 字；禁套话。
判据：删掉这句，读者会不会少知道一件事？不会 → 删。

## 3. 改完实现后必做

1. 找归属主题域 → 按 `README.md` 分类索引定位。
2. 只更新受影响部分：构成 / 数据流 / 规则 / 细节 / 常见问题。
3. 删旧信息：被替代的旧方案直接删。
4. 同步引用：改名 / 改路径后全文搜索，确认无残留。
5. 更新 `必读-项目现状-CONTEXT.md` 的「现状」与「阻塞点」。

## 4. 新建文档

1. 判定归属主题域 → 落对应目录。
2. 命名 `等级前缀-中文作用-英文缩写.md`。
3. 在 `README.md` 分类索引登记一行（唯一详表）。
4. 细节别塞进 `CONTEXT.md` / `INDEX.md`。

## 5. 本项目特有约定

- **内存地址只写在 `MEMMAP.md`**，其它文档指路，不复制表。
- **每条地址必须标注"已实测"或"未确认"**，不允许含糊。
- **坑清单与防回退清单只增不删**，是唯一例外。
- 踩到新坑 → 写进 `PITFALLS.md`，不只留在代码注释里。

## 6. 收尾自检 → 用 `AGENTS.md` 的「交付前自检」清单。
