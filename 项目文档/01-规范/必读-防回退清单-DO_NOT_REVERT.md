# 必读-防回退清单-DO_NOT_REVERT.md —— 别把这些改回去

> 【必读·P0】下列都是**刻意设计**：看着可以简化，一旦被"优化"就退回已知的坏状态。
> 读法：**准备重构 / 简化 / 删冗余前先扫一遍**；要动任一条，先读完「为什么」。
> 边界：一般的坑 → `必读-动手前的坑-PITFALLS.md`。

## 定位方法

- **别用盲扫脚本替代反汇编**（`tools/analyze.py`、`locate*.py`、`scan_*.py`、`find_bullets.py`、`find_pool.py`、`find_moving.py`）。
  为什么：这三条盲扫路线累计耗掉数小时、全部误报；最后靠 capstone 反汇编 5 分钟就拿到子弹结构。
  合法改法：只在**已有确定 stride + 槽内偏移**时，用它们做"基址验证"这一件事。

- **别把浮点扫描值域放宽到 [-50, 1200]**（`tools/analyze.py` 的 `snapshot()` 调用处）。
  为什么：命中 1.52 亿个 float，Python 进程涨到 5.3GB，任务被系统中止。
  合法改法：按已知坐标系收紧 —— x∈[0,384]、y∈[0,448]；并且只扫 ≤4MB 的小块区域。

- **别把 `ref-th06nc-practice/` 当成可随意改的代码**（`项目文档/09-依据/`；上游无 LICENSE，未随仓库分发）。
  为什么：它是第三方只读参考，本项目多数地址由它推导而来。
  合法改法：只读；需要改动时复制出来另存。

## 输入

- **别在未校验前台窗口时发送字母键**（`tools/th06.py` 的 `game_input()`）。
  为什么：`GetAsyncKeyState` 是全局键状态，前台若是 QQ / 浏览器，字母键会变成打字。
  合法改法：发送前比对 `find_windows` 的前台 hwnd；不确定时只发方向键。

- **别把"暂停态"当作默认状态**（所有发移动键的脚本）。
  为什么：暂停时方向键无效，会误判成"输入模拟失效"而重写输入模块。
  合法改法：发移动键前先确认状态，必要时先按 `Z` 解除暂停。

## 地址与常量

- **别在 `tools/offsets.py` 之外再写死游戏地址**。
  为什么：同一个地址曾散在多处 —— `curState` 5 个文件、`BulletManager` 5 个文件、`Lives` 4 个文件，改一处必漏几处。
  合法改法：新地址先加进 `tools/offsets.py`（依据同步写进 MEMMAP），各文件 `from offsets import ...`。
  护栏：`py tools\check_offsets.py` 扫裸地址残留（`tools/disasm.py` 的观察点是函数内偏移，已豁免）。

## 躲避决策

- **别把逐弹判定半径改回统一常数**（`tools/dodge.py` 的 `plan()` / `doomed_gap()` 里的 `threat` / `bthr`）。
  为什么：曾一律按 `PLAYER_R + BULLET_R = 4.25px` 算。实测弹幕有 4×4（r=2.0，占多数）与 6×6（r=3.0）两档，
  原版分档最大到 32×32（r=16.0）—— 统一常数把大玉**少算 13px**，算出来"安全"的位置其实必死；小玉则多躲 1px。
  合法改法：判定半径是**每颗子弹自带的**（`Bullet + 0x5F4` 的 grazeSize，见 MEMMAP §3），
  `read_bullets()` 已返回该列；判定必须先各减各的阈值再取 `min`（先取 min 再减常数等价于退回旧行为）。
  要留余量调 `--safe`；`BULLET_R` 只做兜底。
  护栏：`check_autofire.py` 的 5 条「判定半径·」（同一位置：小玉 +8.75 / 普通 +7.75 / 大玉 −5.25）。

- **别把软项（贴边 / 惯性 / 进攻吸引 / 道具吸引 / 空旷区吸引 / 自动回中）加回安全分**（`tools/dodge.py` 的 `plan()`）。
  为什么：它们与"时间窗最小间隙"同量纲相加，会盖过真实间隙 —— 贴脸弹 + 贴边权重 30 实测选中 gap = −0.25px 的方向；进攻吸引则会为了追 BOSS 主动走进必死方向，道具吸引会为了捡 P 点走进弹幕。
  合法改法：软项只在间隙 ≥ `--comfort` 的候选之间决胜负；紧张档（无方向达到分数线）时也只允许
  间隙 ≥ 0 且与最优相差 ≤ `--risk` 的方向参与。要调强弱改 `--comfort` / `--edge` / `--inertia`
  / `--attack` / `--item` / `--margin` / `--switch` / `--risk` / `--clear` / `--center`。
  护栏：`tools/check_plan.py` 用例 1 / 4 / 6 / 14 / 25 / 26 分别钉住这六项；
  两个新软项由「权重极大也不会选中会中弹的方向」钉住（在固化的真实弹幕帧上跑）。

- **别把紧张档的候选放宽到间隙 < 0**（`tools/dodge.py` 的 `plan()` 紧张档分支）。
  为什么：`risk` 只解决「一紧张就完全不追 BOSS」，不是放松安全。候选一旦允许负间隙，
  就回到「软项覆盖安全」的老路（道具吸引会为了捡 P 点走进弹幕）。
  合法改法：调 `--risk` 改容差（默认 1px，本就落在 horizon 外推误差量级）；`risk = 0` 退回纯躲。
  护栏：`check_plan.py` 用例 26（必死局面 risk 5px 仍选最大间隙）。

- **别把道具吸引改回「瞬时距离」**（`tools/dodge.py` 的 `item_cost()`）。
  为什么：不看下落速度就会退回三个已知坏行为 —— 朝高处道具跑过去干等、追赶不上的
  （道具 y ≥ 432 消失且倒扣 rank）、朝自机上方的道具上追（危险且子弹朝上飞，打不到人）。
  合法改法：时间来自 `vys`（`read_items.py` 已读出，别再当成"只供诊断"丢掉）；
  要调「愿意等多久」改 `--item-wait`，要调「下方牵引多少」改 `ITEM_DOWN_REACH`（别调大）。
  护栏：`check_plan.py` 用例 13b–13e。

- **别为了「多捡道具」把顺路衰减去掉**（`tools/dodge.py` 的 `item_aim_vals()`）。
  为什么：打得到 → 敌人才会死 → 才继续掉道具。旧参数下用户已把道具权重拉到 1000
  （进攻 200），结果自机被道具牵着走、打不到 BOSS，掉落物反而更少。
  合法改法：调 `ITEM_AIM_TOL`（顺路带半宽）/ `ITEM_AIM_FADE`（衰减宽度）或 `--item` 权重。
  护栏：`check_plan.py` 用例 27 / 28（同一道具：有目标时不追、无目标时追）。

- **别把「无威胁源时软项参与排序」改回无条件拦截**（`tools/dodge.py` 的 `plan()` 的 `has_threat`）。
  为什么：清完杂兵 / BOSS 击破后的空档期没有威胁源，安全分恒为 0 < `comfort`，
  软项（含道具吸引）会被整体拦掉 —— 自机全程 `none`，掉落物就在眼前也不去捡。
  合法改法：无威胁源时所有方向都绝对安全，直接让软项决胜负；**有威胁源时仍按安全分数线分层**。
  护栏：`check_plan.py` 用例 12（空档期朝道具走）。

- **别把贴边项改回全局中心吸引**（`tools/dodge.py` 的 `edge_cost()`）。
  为什么：全局吸引与进攻吸引全场对抗，实测把自机钉在原地、水平偏差 53px 打不到敌人。
  合法改法：要调力度改 `--edge`；要改作用距离改 `EDGE_MARGIN`。
  护栏：`check_plan.py` 用例 10（场地中部必须为 0）+ 用例 11（对齐到敌人宽度内）。

- **别把软项的前瞻改回 `horizon`**（`tools/dodge.py` 的 `plan()`）。
  为什么：外推 30 帧(120px) 会把「走一步」当成「走到底」—— 自机要右移 30px 对齐目标，
  被判成「一路撞到右边界」而不敢动（实测水平偏差 27px 打不到）。
  合法改法：软项统一用 `ATTACK_STEP`；要更远视就同时调 `ATTACK_STEP` 与 `EDGE_MARGIN` 并重跑护栏。
  **例外：空旷区吸引用自己的 `--clear-step`**（默认 12 帧 ≈ 53px）—— 这不是违反本条。
  它评价的是「这一带弹多不多」而不是「这一步落在哪」：4 帧的落点彼此只差几十像素，
  而评价半径 110px → 各方向的空旷度高度相关、软项几乎没有区分度（本机实测同帧极差
  0.20、决策差异率仅 1.2%）。前瞻 vs 区分度 vs「最空方向贴着边界」的比例（真实密集快照）：
  4 帧 0.20/2%、8 帧 0.51/2%、12 帧 0.85/2%、16 帧 0.98/12%、20 帧 0.99/38%、25 帧 0.99/78%
  —— 12 帧是「区分度够」与「不把自机往边界赶」的平衡点，别只为了更远视往 20 帧推。
  护栏：`check_plan.py` 用例 11 + `tools/explain_plan.py` 的影子轨迹对比。

- **别把「自动回中」改回全局中心吸引**（`tools/dodge.py` 的 `recenter_cost()`）。
  为什么：与上面贴边项同一个教训 —— 全局吸引与进攻吸引全场对抗、把自机钉死。
  本项**带内恒 0**：离场地中心 ≤ `--center-r`（默认 110px）时完全不干预，只有跑远了才牵引。
  它补的是贴边项够不到的地方，主要是**顶部中间**：那里离左右边界不近、离顶边也可以超过
  60px，贴边项给 0 分，但上方弹幕刚生成、留给自机的反应距离最短，实战最不该久留。
  合法改法：要调力度改 `--center`，要调作用范围改 `--center-r`。
  **别把带内的 0 改成渐变**（那正好等于退回全局吸引）。
  护栏：`check_plan.py` 用例「回中·场地中心为 0」「回中·自由半径处仍为 0」
  「回中·权重极大时选中离场地中心最近的方向」。

- **别把 `--switch`（切换门槛）调到 0.5 以上**（`tools/dodge.py` 的 `SWITCH_MARGIN`）。
  为什么：门槛过大会把「贴边该脱出」「半路该继续对齐」都粘住 —— 实测 1.5 时自机停在中途、
  水平偏差 139px 打不到目标。抖动的主因是软项对抗，已由贴边项局部化与进攻项死区消除。
  合法改法：去抖改 `--margin` / `--inertia`；门槛保持 0.3 量级。
  护栏：`check_plan.py` 用例 2（贴边脱出）+ `tools/sweep_params.py`（门槛扫描）。

- **别把反应延迟加到危险侧**（`tools/dodge.py` 的 `ReactionGate`）。
  为什么：延迟期间自机走的仍是「当前方向」—— 当前方向一旦不再安全、或最优方向不再宽裕，
  等待就是在耗掉已确认的安全窗口，是拿命换「像人」。
  合法改法：调 `--react` 改幅度、`REACT_SLACK` 改「多宽裕才敢等」；判据必须保持
  「当前方向 ≥ `max(comfort, REACT_MIN_COMFORT)` 且最优 ≥ 底线 + `REACT_SLACK` 才允许延迟」。
  护栏：`check_plan.py` 用例 21（危险侧 9 种组合全部零延迟）。

- **别让延迟的安全底线跟着「安全分数线」走**（`tools/dodge.py` 的 `REACT_MIN_COMFORT`）。
  为什么：分数线同时是软项的闸门 —— 为「让更多软项参与排序」把它调到 1px 是合法调参，
  但延迟判据若直接用它，就会连带把延迟闸门从 6px 拉到 1px（实测有人这么调过，延迟随即
  漏进本应即时反应的场面）。二者职责不同，必须取**大者**而非共用。
  合法改法：调底线改 `REACT_MIN_COMFORT`；分数线调高时延迟自动从严，调低时不放松。
  护栏：`check_plan.py` 用例 24（分数线 1px 时 16 种组合仍全部立即执行）。

- **别把 `prev` 改回传 `plan()` 的原始输出**（`tools/dodge.py` 的 `run_session`）。
  为什么：`prev` 必须是**实际执行**的方向（延迟后的）。传 plan 原始输出的话，延迟期间
  inertia 与切换门槛会以为自机已经在走新方向 —— 迟滞建立在错误前提上，动作反复。
  合法改法：延迟层的输出才进 `apply_keys()`，并且只有它回填 `prev`。
  护栏：`check_plan.py` 用例 20 / 22（等就等满、目标反复变也不卡死）。

- **别把 `Lives == 0` 当退出条件**（`tools/screen.py` 的 `screen_of()`）。
  为什么：残机是**备用命**，0 只表示没有后备 —— 旧版在这里退出，脚本一进最后一条命就松键站桩送死。
  该防的是 Continue 画面（`0x4FF0F2 == 0xFF`），那是另一条判据，不该用残机数代理。
  合法改法：`NO_LIVES` 可以继续发键，但 `dying` 与 `retry == 0xFF` 的判定必须排在它**之前**：
  前者让死亡结算完立刻松键（赶在 Continue 出现前），后者保证 Continue 画面一个键都不发。
  护栏：`check_autofire.py` 残机 0 用例（判据顺序 / 结算即退 / Continue 零按键）。

- **别把灵击决策挪到画面判据之后**（`tools/dodge.py` 的 `run_session` 循环开头）。
  为什么：`screen_of()` 见到自机死亡会返回 `DYING` 并让主循环松键退出 —— 死亡窗口还剩 7 帧
  也照退不误，抢救机会被吃掉。被救回后 `dying` 标志还可能滞后，一刀切退出会把已救回的局也结束掉。
  合法改法：灵击跑在画面判据**之前**，窗口内（`state == DEAD 且 respawn > 0`）与已救回
  （state 不再是 DEAD）都继续跑，其余非关卡画面照样退出。
  护栏：`check_autofire.py` 灵击用例（窗口内按 X / 窗口过了退出）。

- **别把必死预判的激光判据放宽回「全部活跃激光」**（`tools/dodge.py` 的 `read_frame()` / `doomed_gap()`）。
  为什么：只有阶段 `1`（发射）会调 `Player__CalcLaserHitbox`，预警 / 消散阶段打不到人。
  放宽回去 = 激光还没释放就先炸一颗（用户实测报过：预警线一出就放灵击，纯浪费）。
  合法改法：要更早炸属于策略选择，先问用户；预警还剩几帧另有用途（`read_lasers()` 的 `totals - timers`）。
  护栏：`check_autofire.py` 的「激光·还在预警（无判定）时不预判炸」「必死判据只留发射中的那条」。

- **别把预警激光的避让塞进安全分**（`tools/dodge.py` 的 `warn_rect_cost()` / `WARN_RECT_W`）。
  为什么：预警期 `pos` 静止、`speed = 0`，「它会不会扫、往哪扫」没有任何信号；
  而它一开火就 +6px/帧横扫（> 自机 4.39px/帧），**横向余量是假的** ——
  它会扫过整个屏幕宽度，只有沿轴线跑出 368px 长的区间才安全，所以要请自机往外走。
  但这件事**只能做软项**：它算的是「逃出区间还需多少」，与碰撞间隙不同量纲，
  混进 `min()` 后那个 −150 会把「撞敌人 −10」这种真威胁盖掉
  （实测症状：自机为了躲激光径直撞进 BOSS）。
  合法改法：`WARN_RECT_W`（权重，默认 80 > 进攻 55）、`WARN_RECT_STEP`（自己的前瞻）、
  `WARN_RECT_ON`（对照开关）都能调；但「安全分只认真实几何」这条不能动。
  护栏：`check_plan.py` 用例 41（代价函数 + plan 决策，且安全分与关闭时逐字一致）。

- **别把激光的判定几何改回「静止线段」**（`tools/dodge.py` 的 `laser_gap()` / `read_frame()`）。
  为什么：① 线段是 `pos + 方向 × [startOffset, endOffset]`，`pos` 只是**轴原点**；
  ② 激光的**轴原点每帧在平移**（Laevatein 实测 +6px/帧，比自机 4.39px/帧还快），
  这个量槽里读不到，只能由 `LaserMotion` 逐帧差分、经 `laser_gap(..., lvx, lvy, ts=ts)` 外推。
  退回静止几何 = 站在激光的必经之路上不动（用户实测报的「躲不开横扫过来的激光」）。
  合法改法：`horizon`、差分阈值 `MAX_STEP`、两类速度的权重都能调；
  但「按**第 t 帧**的线段算第 t 个轨迹点」这条不能省。
  护栏：`check_plan.py` 用例 37–39（横扫带时间维、静止对照、生长阶段、槽复用不伪造速度）。

- **别把激光的朝向写死成当前值**（`tools/dodge.py` 的 `laser_gap()` 的 `lom` 参数）。
  为什么：angle **逐帧会变** —— 实测同一槽连续 19 帧 `pos`/`start`/`end`/`speed` 全不动，
  只有 angle 每帧 +2.25°。按「朝向固定」算，旋转激光的落点就停在当前朝向
  （40 帧差 90°，一条 388px 的激光整片扫过去）。
  合法改法：`LaserMotion.MAX_TURN` 与 `MAX_STEP` 能调；
  但「第 t 帧的朝向 = `angle + ω·t`」这条不能省，槽复用判据也不能退回「角度必须相等」。
  护栏：`check_plan.py` 用例 44（角速度差分、阶段倒退判槽复用、旋转外推 + 旧行为对照）。

- **别把子弹外推改回「匀速直线」**（`tools/dodge.py` 的 `bullet_paths()` 与 `plan(bf=…)`）。
  为什么：新典保留了原版整套 exFlags 机制（MEMMAP §2.1）—— 加速弹每帧 `velocity += accel`，
  转向弹在 `timer >= interval×(num+1)` 那一帧把速度矢量**整体改向**（`0x80` 还朝自机转）。
  退回匀速 = 窗口内落点全错（实测加速弹 10 帧差 27.5px；转向弹转向帧之后整段作废）。
  合法改法：`horizon`、`BULLET_SKIP_DESPAWN`、`bullet_paths` 里 `0x20`/反弹位的取舍都能调；
  但「按原版机制逐帧推进」这条不能省。
  护栏：`check_plan.py` 用例 45–47（抛物线、计时到 hold 就停、转向插值、朝自机转、plan 真吃 bf）。

- **别把敌人当成静止的**（`tools/dodge.py` 的 `enemy_gap()` / `EnemyMotion`）。
  为什么：前瞻窗口里子弹（`vx`/`vy`）和激光（`laser_gap` 的 `ts`）都有速度外推，
  **唯独敌人被当成静止的** —— 而敌人池里根本没有速度字段（MEMMAP §6），
  速度只能像激光一样逐帧差分。BOSS 会移动（Laevatein 实测蕾米莉亚本体逐帧位移，
  AABB 56×56），`horizon` 16 帧就是 16 次误差累积。
  实测：不外推时自机把「冲下来的敌人」那一格算成 +120.8px（安全），
  外推后同一格是 −51.2px（必死）—— 用户报的「撞到敌人身上死亡」就是这个误差。
  合法改法：`EnemyMotion.MAX_STEP`（槽复用阈值）能调；
  但「每个轨迹点按**那一帧**的敌人位置算间隙」这条不能省。
  护栏：`check_plan.py` 用例 42（差分 4 条 + 外推 2 条 + 端到端 2 条）。

- **别去掉 `ENEMY_MARGIN`**（`tools/dodge.py` 的 `plan()` 的敌人分支）。
  为什么：`comfort = 1px` 是用户拍板的手感基准（软项的闸门），于是池内
  「间隙 1px」与「间隙 25px」的余量分差只有 `margin_w`（8 分，且被 `MARGIN_CAP` 截断），
  而进攻吸引 55 / 矩形避让 80 都是几十上百 —— 自机会为了软项收益主动选
  「擦着敌人 1px 过去」。**子弹擦过去是常态，敌人擦过去是死亡**，不能同一个定价。
  合法改法：`ENEMY_MARGIN`（默认 48px）可调，调大 = 离敌人更远。
  护栏：`check_plan.py` 用例 43（输出位仍可用 +20.8px；贴到 42px 变 −9.2px）。

- **别把「九向全负时按最小间隙排」改回去**（`tools/dodge.py` 的 `plan()` 兜底 + `ESCAPE_RANK`）。
  为什么：安全分只留 `min` 会把「还有几帧不在判定圈里」压掉 —— `−8`（下一帧就吃到子弹）与
  `−29`（20 帧内一步都没进圈，只有 40 帧窗口的远端会撞）被当成同一量级，而 `none` 因为
  「不动就不靠近别的威胁」反而胜出。两批实测都死在这上面：
  `113717`（自机在即将开火的激光判定圈里站 59 帧，右移 5.95px / 2 帧就能活）、
  `121323`（离最近 FIRE 激光表面 15px，只因 `LASER_MARGIN=16` 被扣成 −4.69；
  唯一能躲开下一帧大玉的 `down` 被判 −29.35 → 站定，一帧后被打死）。
  合法改法：`ESCAPE_RANK` 可关（对照）；但「全负时改按安全时间结构排」不能退回纯 `min`。
  排序键 = **窗口内 `raw ≥ 0` 的帧数**（`raw` = 纯判定几何，三类各自的余量已减掉）；
  **前置条件不能去掉**：只有「走一步就进判定圈」（`raw0['none'] < 0`）才启用 —— 还安全时余量
  仍是有意义的排序依据（`121449` 实测：贸然启用会把自机推到 y=432 下边界卡死，更早死）。
  护栏：`check_plan.py` 用例 48 / 50（都断言 `scores` 逐字不变）；排序键只看安全量、不看软项不变。

- **别把 `warn_pool` 默认打开**（`tools/dodge.py` 的 `plan()` 紧张档分支）。
  为什么：那条放宽（九向全负 + 有预警线时把候选池放开到全部方向、让软项参与）治的是「站桩」——
  `max(top - risk, 0.0)` 的下限在 `top < 0` 时把池清空，**软项被整条旁路**，而
  「预警激光马上要开火」只有软项知道 → 自机在激光阵里选 `none` 站到底
  （131730 静止 25 帧、123939 静止 223 帧后被打死）。
  但**离线漂亮、实机是错的**（2026-09-27 证伪）：放开后自机确实动了，方向却**朝 BOSS** ——
  `warn_rect_cost` 找的「最近出口」几何上就是上方（自机 y=233 时到上端点 153px、到下端点 215px），
  而上端点正是 BOSS。设计者本意「软项提议往上、安全分否决撞 BOSS 那一步」，
  可**九向全负时安全分的否决机制本身就失效了** —— 站桩与冲 BOSS 是同一缺陷的两面。
  试过无效：`center_w=0` / `attack_w=55` / `risk=20` / 关余量项；唯一能往下走的是关 `warn_rect_cost`。
  合法改法：作为对照试算可以开（`--param warn_pool=True`）；要让自机远离 BOSS，
  得把**敌人位置喂给 `warn_rect_cost`**，不是放开 pool。
  护栏：默认关时 20 例复算「选不动」两侧都是 194/260（逐字一致）；`check_plan` / `check_autofire` 全过。

- **别把低速模式简化成「复用高速规划的结果」**（`tools/dodge.py` 主循环的双速规划）。
  为什么：`plan()` 的间隙是按 `speed` 外推轨迹算的 —— 拿高速轨迹去执行低速，
  等于「以为走得到、实际少走一半」，偏偏埋在最需要余量的宽裕局面里。
  合法改法：门槛（`FOCUS_SLACK`）、迟滞（`FOCUS_EXIT`）、例外（冲线期强制高速）都能改，
  但「慢的那一档必须自己重跑一次 `plan()`」不能省；必死预判同理，要用当前实际速度。
  护栏：`check_autofire.py` 低速用例。

- **别把 `FOCUS_RATIO` 当可调项**（`tools/dodge.py` 顶部常量）。
  为什么：低速 = **精确半速**，是反汇编 + 自机结构常量给的
  （`Player+0x7860` / `+0x7864` = 4.0 / 2.0，斜向 2.82843 / 1.41421）—— 不是调参空间。
  改它 = 让 `plan()` 的外推与实际位移不符。
  合法改法：想改「多宽裕才敢切低速」调 `FOCUS_SLACK`；想关掉用 `--no-focus` / 勾选框。

- **别放宽「必死预判」的触发条件**（`tools/dodge.py` 的 `doomed_gap()` / `BombGuard`）。
  为什么：它是**九向外推全部重叠**才触发 —— 判据为负意味着不炸必死，所以这一炸必然不浪费。
  放宽成「最优方向间隙很小就炸」（例如拿 `plan()` 的 `top < 0` 当判据）会立刻开始白扔炸弹：
  外推 horizon 帧的最小间隙受误差影响，弹幕一密就常态为负。
  合法改法：调 `--bomb-pre` 改前瞻帧数（默认 1 帧，0 = 关掉预判只留死亡炸弹）；
  要更积极地用炸弹，那是用户的策略选择，得先问。
  护栏：`check_autofire.py` 的「安全时不乱炸」「无敌中不预判炸」。

- **别去掉灵击的按住帧数与冷却**（`tools/dodge.py` 的 `BOMB_HOLD` / `BOMB_COOLDOWN`）。
  为什么：bomb 是**按下沿**触发（`0x68A09` 与上一帧输入位图比较），同帧 down+up 会被游戏
  轮询漏掉，等于没按；一直按着则只有第一帧算，死亡窗口里想再按一次也按不出来。
  合法改法：改幅度可以（`BombGuard(hold=…)`），但必须保持"按下 → 跨若干帧 → 松开"这个形状；
  `X` 与方向键同走 `apply_keys`，别绕开它单独发键（否则退出路径会漏松键）。
  护栏：`check_autofire.py` 的「按下沿只发一次」。

- **别让「空档期放宽等待」外溢到有威胁时**（`tools/dodge.py` 的 `plan()` 的 `wait_eff`）。
  为什么：`ITEM_WAIT_IDLE` 只在**场上没有威胁源**时生效 —— 那时没有中弹风险，站在落点下方
  等不算干等。一旦有弹 / 敌人 / 激光还这么干，就退回「为道具站桩挨打」的老路。
  合法改法：调 `ITEM_WAIT_IDLE` 的时长、或调 `--item-wait` 改有威胁时的尺度；
  判据必须继续挂在 `has_threat` 上。
  护栏：`check_plan.py` 用例 16b–16d（空档期去等 / 有威胁时选择不变）。

- **别让冲线吸引叠加在进攻/道具吸引之上，也别把它加进安全分**
  （`tools/dodge.py` 的 `plan()` 的 `poc` 分支）。
  为什么：冲线期 `attack_cost` 的「冲过头顶」惩罚（×2）专治输出位 —— 冲线时往上冲正是目的，
  两者叠加会在收集线下方几像素处互相顶住，冲线永远差一口气（护栏实测：过冲区被拉回输出带）。
  冲线吸引是软项：`poc_w = attack + item + POC_W_EXTRA` **替代**两者（不是叠加），
  且只在 charging 时存在；安全分永远压过它 —— 上方被弹幕堵死时冲不上去，
  限时 `POC_TIMEOUT` 一到放弃进冷却，绝不硬闯。
  合法改法：调触发改 `--poc-min`（价值阈值）/ 勾选开关（`poc`）；调吸引强度改 `POC_W_EXTRA`；
  调限时/冷却改 `POC_TIMEOUT` / `POC_COOLDOWN`。
  护栏：`check_plan.py` 用例 32–33（权重 500 拉不进死路 / 过冲区仍朝上）
  + `check_autofire.py` 道具线用例（满火力才传目标）。

- **别把 state-2 散射物的 vy 字段当下落速度，也别把它算进可转化价值**
  （`tools/dodge.py` 的 `read_frame()`）。
  为什么：散射 60 帧插值期间该字段被出生点 y 覆写（垃圾值）；且原版 PoC 转化判据在
  `state != 2` 分支里 —— 散射物**永远**不会被收集线转化，把它算进 `poc_val` 会让
  触发阈值虚高（冲上去什么也没吸到）。散射结束后 vy 清零、从静止重新 +0.03 加速。
  合法改法：位置用 targetPosition 近似、vy=0、`delays`（平均 30 帧）平移到达/出局时刻；
  `poc_val` 只合计 state-0；state-1（追踪中）自投罗网，剔除出吸引集。
  护栏：`check_plan.py` 用例 34–35（三态分拣 / 散射 +60 帧判干等）。

## 关卡推进

- **别把 `STAGE_SWITCH`（curState=3）当普通非关卡画面退出**（`tools/dodge.py` 的 `run_session`）。
  为什么：那是关卡之间的过渡态 —— 游戏自己会 `currentStage++` 并把下一关载入；在这里退出
  等于「打完一关就停」，那正是用户报的原始问题。
  合法改法：改等待上限 `ADVANCE_TIMEOUT_S`；要「打完就停」用 `--no-advance` 或取消勾选。
  护栏：`check_autofire.py` 的进关用例（过渡不退出 / 关掉后退回旧行为）。

- **别在有威胁源时轻点 Z 推进对话**（`tools/dodge.py` 的 `run_session` / `StageFlow.tap_due`）。
  为什么：轻点要先松开按住的 Z —— 等于在弹幕里停一次连射；而战斗中本来也没有对话要推进。
  合法改法：调节奏改 `ADVANCE_TAP_S`；判据必须继续挂在「场上没有弹幕 / 敌人 / 激光」上。
  护栏：`check_autofire.py` 的对话用例（有威胁源时轻点次数必须为 0）。

- **别在 Continue 画面或关卡过渡里做「预备接管」**（`tools/dodge.py` 的开场段）。
  为什么：预备接管会先按住一个方向键；Continue 画面上的方向键会把「是」拨到「否」，一局作废。
  合法改法：预备接管只在 `code == 'IN_GAME'` 时做；过渡期间连开场的 Z 也不按。

- **别把 `RELOAD`（curState=0 / 12）改回「未知场景 → 退出」**（`tools/screen.py` 的 `screen_of`）。
  为什么：符卡练习按 Z 重试时依次经过 `12 → 0 → 2`，各只 1~2 帧；判未知场景 = 每重试一次就退出，
  自机随后静止被打死。曾连踩两次（先漏 12，补完又漏 0）。
  合法改法：只改等待上限 `RELOAD_TIMEOUT`；真的要「一进重载就停」应加显式开关，别改判据。

- **别把失败菜单（`isInRetryMenu=0xFF`）改回「一律退出」**（`tools/screen.py` + `run_session`）。
  为什么：这一位**同时**覆盖普通关卡的 Continue 与符卡练习的 "Failed..."；
  一律退出会让练符卡时"死一次就永久停手"，那正是用户报的原始问题。
  合法改法：默认仍然一个方向键都不发（拨光标）；要自动继续就开 `--resume` /
  GUI「失败菜单按 Z 继续」—— 按 Z 在符卡练习下是「重试」，普通关卡下是「续关」（用户自己权衡）。

- **别删 `tools/watch_live.py`**（只读观测器）。
  为什么：它是唯一能回答「谁打中了我」的工具 —— 避弹日志只有一行"间隙"，看不到是哪颗弹、
  哪条激光、以什么参数过来的；把它删掉等于下次死因回到靠猜。
  合法改法：加输出项随意；`--csv` / `--log` / `--quiet` 的语义要留着（后台挂着看靠它们）。

## 玩家让位

- **别把让位判据简化成「最近 N 秒内有按键」**（`tools/dodge.py` 的 `watch.yielding`）。
  为什么：人一直按着方向键时时间窗会过期，脚本随即把手柄抢回来 —— 那正是最不该抢的时刻。
  合法改法：判据保持「时间窗 **或** 此刻仍按着键」；调时长改 `--human-idle`。
  护栏：`check_autofire.py` 的让位用例。

- **别在让位时无脑 `release_all()`**（`tools/dodge.py` 的发键段）。
  为什么：SendInput 的抬键同样会改系统键状态表，硬松会把玩家按住的右方向顶掉。
  合法改法：`release_all(held, skip=watch.physical())` —— 玩家按着的键只划掉、不发抬键。
  护栏：`check_autofire.py`「玩家按着的键不抬」。

- **别去掉注入键的双判据**（`tools/th06.py` 的 `INJECT_TAG` + `tools/human_watch.py` 的回调）。
  为什么：只看 `LLKHF_INJECTED` 或只看键状态都不够 —— 少了任一判据，让位就可能被脚本自己
  发的键触发（表现：一开枪就让位，自机再也不动）。
  合法改法：两个判据一起用；换标记就同时改 `th06.INJECT_TAG` 与钩子回调。
  护栏：`py tools\human_watch.py` 的注入测试（注入事件 > 0 且真实按键为 0）。

## 控制台与配置

- **别把功能自述塞回日志窗口**（`tools/dodge_gui.py` 的 `App.__init__` 与 `_build_log()`）。
  为什么：启动时十几行功能介绍把日志窗口刷满，真正的运行记录被顶出视野；用户明确要求日志只记运行事件。
  合法改法：新能力的说明写进对应滑条 / 勾选的 `PARAM_HELP`（悬浮说明）与 `04-调参/相关-参数速查-TUNING.md`。

- **别给悬浮说明加回 `★` / `**` 等装饰标记**（`tools/dodge_gui.py` 的 `PARAM_HELP` 与各勾选 `Tooltip`）。
  为什么：Tk Label 不解析 Markdown，`**X**` 原样显示成星号；用户要求统一为陈述句式。
  合法改法：需要强调就写进句子（「上限 0.5，超过会…」），用分号断句，不加标记。

- **别把整个 `cfg` 写进 `dodge_params.json`**（`tools/dodge.py` 的 `save_saved`）。
  为什么：`cfg` 里混着 `dry` / `frames` / `period` / `resume` 这类**运行状态**。固化它们会让
  下次启动带病开门（例如默认 `dry=True` 就一个键都不发，或带着帧数上限跑几十帧就退出）。
  合法改法：只写 `default_params()` 认得的键；要新增可保存项就加进 `default_params()`。
  护栏：`save_saved()` 按 `default_params()` 的键集合过滤。

- **别让保存的默认值反过来改代码常量**（`tools/dodge.py` 顶部常量区）。
  为什么：出厂默认是「重启控制台就能回去」的退路。若保存动作去改 `.py` 文件，就再没有干净的
  基准可对比，也踩上「改了 `tools/` 要重启控制台」的坑。
  合法改法：文件缺失 / 被删即回出厂；用户要永久改出厂才动 `default_params()`。

- **别把出厂默认里那几个「看着像旧值」的数字改回去**（`tools/dodge.py` 的 `default_params()`
  与顶部常量区：`comfort=1` / `safe=0` / `react=7` / `switch=0.4` / `warn_dist=10` / `poc_min=0` /
  `standoff=99` / `item=50` …）。
  为什么：这一组是用户实机调校后**明确要求替代出厂默认**的（含文档先前标为「旧极值、等于把唯一
  安全闸门整个放开」的 `comfort=1`）—— 保留是用户拍板的结果，不是遗漏。改掉等于悄悄换掉他的手感基准。
  合法改法：改出厂默认要用户点头；用户后续自己改的走 `dodge_params.json`（保存值），两者别混。

## 工具链

- **别去掉 `Process.read` 的锁**（`tools/winmem.py`）。
  为什么：它复用 `_buf` 与返回长度，GUI 主线程与躲避线程并发读时实测 33% 长度错位，

## 方案边界

- **别把"无敌补丁"当作目标实现**（`MEMMAP.md` §5 的 `0x6AA9D` / `0x6ACF2`）。
  为什么：用户明确要的是**自动躲避**；无敌只作为最后后备。
  合法改法：仅在躲避开销确实无法做到时，先问用户。
